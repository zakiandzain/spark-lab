# The build track

Eight lessons. About twenty minutes each. Nothing is locked.

## 1. Hello Grok

Grok is a teammate you brief. You are the director. A useful first message names who it is for, what they can do in the first minute, the look, and what version one skips.

## 2. Vibe coding

The loop: brief → draft → use → steer. One dial at a time. "Night skatepark, grainy, huge score" is a look. "Make it better" is not.

## 3. How apps work

Three layers: interface (what you see), state (what it remembers), events (what a tap does). Components are reusable pieces of the screen.

## 4. Prompt like a builder

Build brief template: audience, job, interface, feel, data, cuts, check. Version-one cuts stop Grok from building a startup on a Tuesday night.

## 5. Code without fear

Enough to read a draft: variables, functions, `if`, arrays, components, `useState`. Ask Grok "what does this remember, and what happens on tap?"

## 6. When it breaks

Broken is the job. A debug message has: what you tried, what you expected, the error quoted, when it started. Do not say "it doesn't work."

## 7. GitHub for real

Repo = project folder with history. Commit = save point. Branch = try an idea without breaking main. Pull request = propose a merge. Grok writes. GitHub remembers.

## 8. Ship something

Version one is small: one user, one job, phone, save on this device, a look that is a choice. The capstone is a paste-ready brief.
